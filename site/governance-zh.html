SPEC-007 治理缺口分析

** 版本： 1.0.0主題：** OSTF SPEC 治理規則書（機密來源，SPEC-004 保管）對照現行 Spec-007 文件標準（README 權限等級 L0–L5、spec-007-verified.en.md、計算台架、存檔政策）。

前置結論： 規則書是一份強力的程序性治理文件，卻是薄弱的認識性文件。它規範誰可以更改 SPEC、如何更改，卻沒有任何條款要求 SPEC 內的主張必須經過驗證、具備來源、或可測試。Spec-007 標準走得更遠：主張唯有在台架測試或機構來源支持下方得晉升。雙方都不完全涵蓋對方；正確的終態是採用規則書的生命週期機制，並保留 Spec-007 的證據閘門。

逐條對照矩陣

規則書條款 Spec-007 現行標準 符合度
第一條 — 權威、目的、對審計系統的可追溯性 不可變基線附 SHA-256 錨定；archives/ 里程碑；README 權限等級 部分重疊。 規則書指名「Alpha State 審計系統」（不可驗證輸入）；Spec-007 使用具體雜湊值＋存檔目錄。Spec-007 的做法更強且可執行。
第二條 — 層級與編號（核心編號、子 SPEC、保留號） 等級系統（L0 不可變記錄 → L1 已驗證 → L2 證據 → L3 衍生 → L4 測試 → L5 輸入） 軸向不同，互為補充。 規則書按文件編號分層；Spec-007 按認識權威分層。合併可行（見建議）。
第三條 — 角色（編輯、理事會、倫理、海軍部；AI 僅顧問） 紅隊分析與 AI 衍生設計輸入內容降入 L5 機密輸入；倫理內容除非與工程相關否則排除 精神一致。「AI 系統不對 SPEC 治理投票」與 Spec-007「設計輸入零工程權威」的規則相符。

第六條 — 版本化（MAJOR.MINOR.PATCH、核准層級、歷史節） Spec-007 文件帶日期／狀態但無語意化版本或版本歷史 缺口（Spec-007 側）。 L1/L3 文件採用 semver 與版本歷史節。
第七條 — 審查與維護（年度＋觸發式） Spec-007 有持續紅隊審查但無排程審查 缺口（Spec-007 側）。 L1 加入年度審查日期＋觸發審查條款（例：新供應商數據、法規變更）。
第八條 — 退役／取代、存檔、「退役後永不刪除」 規則書：退役 SPEC 不得刪改。Spec-007：原件永不編輯；錯誤主張永不刪除，僅在 L2 標註 一致且相容。 Spec-007 的規則是嚴格超集（自第一天起即不可變，非僅退役後）。
第九條 — SPEC 登記冊（狀態、版本、編輯、核准記錄） 無登記冊；README 缺狀態／版本／編輯欄 缺口（Spec-007 側）。 增設登記表（見建議）。
第十條 — 實施與合規監控、豁免 Zig 台架測試即為可執行的合規監控；無豁免機制 缺口（規則書側）。 規則書的合規靠「AIWO 軍團監控」（未定義輸入）；Spec-007 有可重現測試。僅在有需要時為 Spec-007 增設豁免規則——台架失敗本已阻擋晉升。
第十一條 — 自我修訂（一致同意／72 小時批准） Spec-007 無自我修訂規則 缺口（Spec-007 側）。 L1 晉升規則（README §規則）充當非正式對等物；應予正式化。
第十二條 — 採用 不適用（文件為專案構件） 不適用

相對於 Spec-007 標準，規則書缺了什麼

  1. 無真相閘門。 規則書沒有任何條款要求 SPEC 的主張在發布前經過驗證。按規則書原文，spec-007.md 中那些未經驗證的錯誤數字（錯置的算術、不匹配的流量、Novec 溫度）可經表決採用而零認識檢查。Spec-007 的晉升規則（須有測試或來源）正好堵住此洞。
  2. 無可執行驗證。 規則書無測試台架要求、無可重現性規則、無「數字必須可計算」條款。
  3. 無不可變基線。 規則書的不可變性僅適用於退役後；Spec-007 要求原件永不更改，更正累積於獨立的晉升層。
  4. 無條件主張分類法。 Spec-007 區分 VERIFIED／VERIFIED-WITH-CORRECTION／EXTRAPOLATION／UNSUPPORTED／CONTRADICTED。規則書無對應物。

Spec-007 標準應自規則書採納的部分

  1. 為 SPEC-007 建立 SPEC 登記冊條目，附狀態欄（草案／現行、編輯、版本）——每份文件一列，隨里程碑更新。
  2. L1/L3 文件採用語意化版本＋版本歷史，使未來數值變更可審計。
  3. 觸發審查條款：當 (a) 引用數據表變更、(b) 取得供應商報價、(c) 合格實驗室量測到來、(d) UN 1402 或相關法規文本變更時，審查 L1。
  4. 正式提案記錄：追溯記錄 SPEC-007 的問題陳述與安全／倫理評估，引用 spec-007-research-dossier.md 既有的危害登記冊。

建議合併方案（提案中，未施行）

  • 將規則書第八條（退役）與第三條（角色、AI 僅顧問）原樣引入 Spec-007 流程。
  • 向規則書（或 L1 本地治理附錄）加入 Spec-007 晉升閘門：(1) 不可變基線；(2) 主張評級；(3) 台架強制數字；(4) 里程碑存檔。
  • 將 README 的 L0–L5 階梯視為本目錄對規則書第二條的本地實作。

結論

接近度估計： 規則書涵蓋 Spec-007 文件標準約 60–70% 的程序面，而 Spec-007 的證據／驗證機制涵蓋規則書全無的部分。合併則構成完整的治理系統；分離則規則書管的是無真相的流程，而本目錄執行的是無流程的真相。存檔 archives/spec-007-governance-gap-analysis-20261004/ 記錄了本次對照。
