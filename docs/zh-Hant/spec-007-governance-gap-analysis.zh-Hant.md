# SPEC-007 治理缺口分析

**主題：** OSTF SPEC 治理規則書（機密來源，SPEC-004 保管）對照現行 Spec-007 文件標準（README 權限等級 L0–L5、`spec-007-verified.en.md`、計算台架、存檔政策）。
**版本：** 1.1.0

**前置結論：** 規則書是一份強力的**程序性**治理文件，卻是薄弱的**認識性**文件。它規範*誰可以更改 SPEC、如何更改*，卻沒有任何條款要求 SPEC 內的主張必須**經過驗證、具備來源、或可測試**。Spec-007 標準走得更遠：主張唯有在台架測試或機構來源支持下方得*晉升*。雙方都不完全涵蓋對方；正確的終態是採用規則書的生命週期機制，**並**保留 Spec-007 的證據閘門。

**2026-10-15 狀態註記：** 本審查所指出的中繼資料與採用權限缺口，現已在治理語料層級以機械方式封閉。現行文件帶有版本化前置欄位與修正後之創始階段權限語句；封存正典文件保持不變，改由雜湊錨定之中繼資料覆疊綁定。`assets/gov-metadata.json` 為去識別公開投影：僅報告文件數量、權限狀態、審查狀態與摘要值——不含機密本文或官員姓名。

## 相對於 Spec-007 標準，規則書缺了什麼

1. **無真相閘門。** 規則書沒有任何條款要求 SPEC 的主張在發布前經過驗證。按規則書原文，`spec-007.md` 中那些未經驗證的錯誤數字（錯置的算術、不匹配的流量、Novec 溫度）可經表決採用而零認識檢查。Spec-007 的晉升規則（須有測試或來源）正好堵住此洞。
2. **無可執行驗證。** 規則書無測試台架要求、無可重現性規則、無「數字必須可計算」條款。
3. **無不可變基線。** 規則書的不可變性僅適用於*退役後*；Spec-007 要求*原件*永不更改，更正累積於獨立的晉升層。
4. **無條件主張分類法。** Spec-007 區分 VERIFIED／VERIFIED-WITH-CORRECTION／EXTRAPOLATION／UNSUPPORTED／CONTRADICTED。規則書無對應物。

## Spec-007 標準應自規則書採納的部分

1. **為 SPEC-007 建立 SPEC 登記冊條目**，附狀態欄（草案／現行、編輯、版本）——本處已實作，並與語料層級中繼資料驗證配對。
2. 受治理文件採用**語意化版本＋版本歷史**——現行 SPEC 已實作；封存文件以覆疊取得相同中繼資料，使正典本文保持不變。
3. **觸發審查條款**：當 (a) 引用數據表變更、(b) 取得供應商報價、(c) 合格實驗室量測到來、(d) UN 1402 或相關法規文本變更時，審查 L1。
4. **正式提案記錄**：追溯記錄 SPEC-007 的問題陳述與安全／倫理評估，引用 `spec-007-research-dossier.md` 既有的危害登記冊。

## 結論

**接近度估計：** 規則書涵蓋 Spec-007 文件標準約 *60–70% 的程序面*，而 Spec-007 的證據／驗證機制涵蓋規則書全無的部分。合併則構成完整的治理系統；分離則規則書管的是*無真相的流程*，而本目錄執行的是*無流程的真相*。存檔 `archives/spec-007-governance-gap-analysis-20261004/` 記錄了本次對照。
