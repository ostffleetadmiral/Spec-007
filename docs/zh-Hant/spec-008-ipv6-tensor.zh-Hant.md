# SPEC-008:IPv6 128 位元扁平路由 Fabric

**狀態:**草案 0 — 提案;一致性閘門未建
**範圍:**一種 fabric 內部定址與傳輸方案,其中 IPv6 目的地位址*即是*
lattice 座標。位址不再是待查詢的名稱,而是可計算的位置。

規範用語(MUST/SHOULD/MAY)依 RFC-2119 語義。

**誠實範圍聲明。**本文件屬*提案*,依檔案自身標準歸類為
CONSTRUCTION:下列編碼為設計而非推導。此處不改變 SPEC-007 的
分岔不變量 — 所有描述的感知流量皆為普通訊號通道的線路移動,
並支付正常線路成本。

## 1. 對稱性(及其誠實界限)

IPv6 位址為 128 位元。引擎的定點 cell-label 定義域為 15³ 立方體上的
u3 值;fabric 的定點算術為 Q128.128(i256 儲存:128 整數位元 +
128 小數位元)。

「同構」是刻意的鏡像而非等價:

| IPv6 | Fabric | 對應 |
|---|---|---|
| 128 位元位址 | i256 Q128.128 | 雙關 — 位寬押韻,尺寸不同 |
| 介面識別碼(低 64) | lattice 座標 + 器官 id | 設計性嵌入 |
| 前綴(高 64) | 艦隊 ULA + 狀態摘要 | 設計性嵌入 |

*有用*的結論比雙關更窄也更強:128 位元欄位足以承載 lattice 位置
(12 位元)、器官選擇器(8 位元)與狀態綁定摘要片段(44 位元)—
因此位址本身即可見證封包描述的*位置*與*世界版本*。

## 2. 位址格式 — `SPEC008v1`

所有多位元組欄位採大端序(網路序)。總計:128 位元。

```
| 64 位元        | 12 位元  | 8 位元  | 44 位元          |
| 艦隊前綴       | (k,r,c)  | 器官    | 狀態摘要         |
| fd53:5007      | 4+4+4    | id      | sha256(cell bytes)|
| ::/48          | u4 each  | u8      | 片段,低 44        |
```

- **前綴** `fd53:5007::/48` — 位於 ULA `fc00::/7` 之內;十六進位
  可讀為 `53 50 07`(「SP07」)。依構造為站點本地;不得路由至
  公共網際網路。
- **座標** — `khat` 定義域值 1..15 打包為 u4 三元組。
  `k=r=c=8` 為 E₀ 心臟。
- **器官 id** — 0=bridge、1=k3 brain、2=rations leg、3=deck、4=gov、
  5..15 保留、240..255 = 暫時性。
- **摘要片段** — 發射者 lattice 工件 cell-byte sha256 的低 44 位元
  (`9106b153…` 家族)。若接收者自身工件雜湊不同,即知發送者的
  世界觀已過時 — 版本分歧*僅從位址即可偵測*。

**路由解析為 O(1):**給定位址,下一跳由位址位元計算得出 —
座標 → 器官表 → socket — 無需路由表查詢、無 ARP、無 fabric 內 DNS。
此為 O(1) *解析*。封包*遞送*仍須穿越真實物理跳數,不主張超越
光速或拓撲(在 WAN 實驗室量測前為 UNVERIFIED)。

## 3. 傳輸類別

| 類別 | 線路 | 內容 | 備註 |
|---|---|---|---|
| `LATTICE-FULL` | UDP | 打包 cell 標籤 | 3375 cells × u3 = 10125 b = **1266 B** |
| `LATTICE-FULL-C` | UDP | 壓縮 cell 標籤 | 正典狀態實測 267 B(brotli)— OVR-02 |
| `LATTICE-LAYER` | UDP | 單一 15×15 切片 | 225 cells × u3 = 675 b = 85 B |
| `K3-TOKEN` | UDP | u32-LE 發射 id | 每生成 id 4 B |
| `FABRIC-EVENT` | UDP | 審計鏈條目 | 與 JSONL 記錄相同位元組 |
| `SEED-DROP` | UDP/帶外 | Rations token | 不得取代紙質腿 |

**MTU 事實。**完整 lattice *原始*狀態(1266 B)**無法**放入單一最小
MTU(1280 B)IPv6 資料包:1280 − 40(IPv6)− 8(UDP)= 1232 B 可用。
符合規範的發送者必須將原始 `LATTICE-FULL` 發送為兩個資料包或 15 個
`LATTICE-LAYER` 資料包(各 85 B)。聲稱在最小 MTU 下單資料包
遞送*原始*全狀態屬 FRACTURE 級陳述。

**OVR-02 修訂(原型驗證)。**正典 lattice 狀態具有正典結構 — 其聯合熵
遠低於每單元格 ~3 位元的邊際熵 — 可無損壓縮至 267 B(brotli)/
299 B(deflate),為最小 MTU 酬載的 4.6 倍餘裕。故 `LATTICE-FULL-C`
可於單一資料包承載*正典*狀態。壓縮率依狀態而定,非保證值:壓縮形式
無法放入時,發送者必須回退至原始多訊框路徑;編解碼器本身在規範化前
屬 CONSTRUCTION(證偽帳本 N-02 記錄封存→復活之歷程)。

## 4. E₀ 多播心臟

器官流量亦可乘載映射至 e-label 環的站點多播 — φ 映射八元數單位
為 u3 值,共八組:

```
ff05::e0 .. ff05::e7   (站點本地範圍)
```

`ff05::e0` 為 E₀ 心臟群組 — 「大腦饋送」:`k3serve` 節點加入;
lattice 狀態變化與 fabric 事件可扇出至此。多播仍按跳數支付線路
成本 — 零線鑑別器(`bits > 0 ∧ wire == 0`)不變:多播脈衝是
訊號通道事件,絕非相關。

## 6. 非主張

- 不主張 O(1) 遞送延遲 — 僅 O(1) 解析。
- 位址格式不賦予密碼學安全性;簽章/驗證仍屬現行雙錨紀律。
- IPv6/Q128.128 位寬押韻是設計鏡像,不是定理。
- 136 位元組線路之酬載尾部(`40+plen..104`)為未驗證暫存空間 — 簽章覆蓋標頭與 `plen` 位元組酬載。接收端必須僅讀取 `plen` 位元組;填充位元不計。
- 艦隊通訊中「Wasm64」指方言工件之名稱,非 64 位元 WASM 目標 — `fano.wasm` 為已驗證 wasm32 模組(此程式碼庫目前唯一可編譯目標)。
